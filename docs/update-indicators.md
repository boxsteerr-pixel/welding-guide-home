# 手册更新红点协议

## 操作规则

- 范围：Home + 108、102、122、202、401、411、502；101 不参与自动红点，保持生产基线不变。
- 每次正式发布内容时，增加对应 `data/manual.json` 的 `machine.manualVersion`（例如 0.1.0 → 0.2.0），同时更新 `lastUpdated`。只改日期不触发新版本提示。
- 每次内容发布仍须按原有流程验证和更新该设备自己的 Service Worker 缓存版本；红点不负责强制更新 PWA。
- Home 打开、返回、重新可见或恢复联网时读取七台手册的版本。
- 第一次检测到未查看版本会显示红点；不存在“自动假定已查看”的初始化。
- 点击不消点；手册数据通过原有校验、内容成功渲染后才写入该版本的已查看记录。
- 离线旧内容只记录实际加载的旧版本，不会确认最新版本已查看。
- 直接扫描设备二维码进入，同一来源、同一存储环境下也会记录已查看版本。
- Home 不缓存设备内容，不控制设备 Service Worker，不删除设备缓存。

## 存储与异常

本地键：`welding-guide-updates:latest:<machineId>`、`welding-guide-updates:seen:<machineId>`。
生产部署同源为 https://boxsteerr-pixel.github.io，所以同一浏览器的这些仓库可共享最小版本状态。
Home 只保存版本号，不保存设备具体内容。失败或离线保留最后已知状态。
记录仅属于当前浏览器/设备；清理网站数据会清除记录。不同浏览器及部分系统的独立安装 PWA 可能隔离存储，不能保证跨容器同步。
本地预览须让 Home 和七台设备使用同一域名与端口（localhost 与 127.0.0.1 是不同来源）。
若禁止本地存储，手册仍可使用，但红点持久化无法保证。
每台设备保留独立 `js/update-state.js` 副本，不使用其他仓库脚本。
更新协议统一修改时同步各副本，并运行 Home 的 `tests/updates-test.mjs`。

## 发布范围

首次启用须发布 Home 与七台新设备仓库，101 不操作。Home 使用 v26 缓存，七台设备分别使用各自的 v5 缓存。设备蓝色页头左上角的小房子返回统一入口，随页头滚动，不悬浮；Home 本身不显示小房子。
